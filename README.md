# Редактор фигур

Приложение на Java Swing. Используется разделение MVC:
модель хранит состояние, представление отображает его,
контроллер обрабатывает действия пользователя.

## Запуск

Дважды нажмите `run.bat`. Выберите фигуру кнопкой внизу окна.
Кнопка «Очистить» очищает холст. При изменении размеров окна фигура
остаётся в центре.

## Сборка после изменения кода

Запустите `build.bat`, затем `run.bat`.
В терминале также можно выполнить `mvn package` и
`java -jar target/shape-prototype-1.0-SNAPSHOT.jar`.

Нужны JDK 17 или новее и Maven. Внешние библиотеки для приложения
не требуются: Swing входит в Java. Maven загружает плагины сборки
при первой сборке; для неё нужен интернет.

В IntelliJ IDEA откройте `pom.xml` как Maven-проект и запустите
`com.example.app.Application`. Установленный Maven находится в
`%LOCALAPPDATA%\Programs\ApacheMaven\apache-maven-3.9.9`.

## Структура программы

| Пакет | Классы | Ответственность |
|---|---|---|
| `app` | `Application` | Запуск и связывание компонентов |
| `model` | `EditorModel`, `ShapeType` | Выбранная фигура и каталог доступных фигур |
| `shapes` | `Shape`, `Ellipse`, `Circle`, `Rectangle`, `Square`, `RoundedRectangle` | Данные и геометрия фигур |
| `view` | `ShapeFrame`, `ShapeCanvas` | Окно, кнопки, строка состояния и рисование |
| `controller` | `EditorController` | Выбор фигуры, очистка и обновление интерфейса |

## Как проходит действие

1. `Application.main()` создаёт модель, окно и контроллер в потоке Swing.
2. Контроллер подключает свои методы к кнопкам окна.
3. Нажатие кнопки вызывает `EditorController.select(type)`.
4. `EditorModel.select()` создаёт фигуру через `ShapeType.createShape()` и сохраняет её.
5. Контроллер передаёт выбранную фигуру и текст состояния в `ShapeFrame.display()`.
6. `ShapeCanvas` вызывает `repaint()`, после чего Swing вызывает `paintComponent()`.
7. Холст получает цвет через `getColor()`, геометрию через `geometry()` и рисует контур.

Очистка проходит по тому же пути: контроллер вызывает `model.clear()` и обновляет окно.
В модели отсутствие выбранной фигуры обозначено `null`; холст в этом случае остаётся пустым.

## Что объяснить на защите

- **Инкапсуляция:** выбранная фигура скрыта в `EditorModel`, цвет скрыт в `Shape`;
  изменение состояния выполняется методами.
- **Наследование:** `Circle` — частный случай `Ellipse`, `Square` — частный случай
  `Rectangle`, `RoundedRectangle` расширяет `Rectangle`.
- **Абстракция:** `Shape` задаёт общий контракт `geometry()`.
- **Полиморфизм:** холст работает с типом `Shape`, а конкретный метод `geometry()`
  определяется фактическим классом фигуры.
- **MVC:** модель не содержит кнопок и не рисует на экране; рисованием занимается
  представление, а обработкой пользовательских действий — контроллер.
- **Фабричный метод:** `ShapeType.createShape()` создаёт фигуру выбранного типа.
- **Координаты:** фигуры создаются относительно точки `(0, 0)`, а холст переносит
  начало координат в свой центр. Старые фиксированные смещения больше не нужны.
- **Проверка данных:** размеры должны быть положительными, скругление — неотрицательным.

Модель использует стандартные типы AWT для цвета и геометрии, но не зависит
от элементов интерфейса Swing. Контроллер обновляет окно явно;
механизм наблюдателей для этого небольшого приложения не используется.

## Что изменилось по сравнению с исходным вариантом

В исходной версии окно создавало фигуры и обрабатывало выбор, холст был вложенным
классом, а фигуры сами рисовали себя через `draw(Graphics)`.
Теперь обязанности разделены между отдельными классами, холст вынесен,
создание фигур собрано в каталоге, а фигуры возвращают геометрию через `geometry()`.
Наследование фигур и поведение приложения сохранены.
